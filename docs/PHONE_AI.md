# 手机端 AI · 能力与权限说明

> 这份文档说明手机上的「小伴」是谁、能干什么、怎么调工具、有什么权限。
> 版本：v2.1.0 ｜ 2026-11-03

---

## 一、身份

**名字**：小伴
**位置**：住在 WH 的 Android 手机里（vivo V2445A）
**角色**：三端里的「执行端」——PC 是大脑，手机是手，机器人是身体

**它不是**：
- 不是客服，不是通用助手
- 不是 PC 端的替代品（PC 才有完整工具集和记忆库）
- 权限比 PC 端小（这是故意的，防止它乱来）

**说话方式**：口语、短句，一次一两句，不超过 60 字。

---

## 二、两种运行模式

### 模式 A：PC 在线（默认）
```
手机 App → 加载 PC 的聊天界面 → 用 PC 的大脑
```
- 工具走 PC 的 51 个工具（能控电脑、能查记忆、能联网）
- 速度快、能力全

### 模式 B：PC 离线（自主模式）
```
手机 App → 原生聊天界面 → 直接调 DeepSeek 官方 API
```
- 屏幕显示「电脑连不上，我先自己干着。」
- 只有 7 个本地工具（见下）
- **带着记忆**（PC 在线时同步过来的 12 条长期记忆）
- 最多 8 轮工具调用

## 三、本地工具（离线可用）

模型每次输出一个 JSON 决定做什么：

```json
{"tool": "ui_tree", "args": {}}
{"say": "已经帮你打开了"}
```

| 工具 | 作用 | 参数 | 示例 |
|---|---|---|---|
| `ui_tree` | 读当前界面结构（文字+坐标+可点击） | `limit`（默认60） | `{"tool":"ui_tree","args":{"limit":80}}` |
| `click` | 按文字点按钮 | `text` | `{"tool":"click","args":{"text":"发送"}}` |
| `click_xy` | 按坐标点 | `x`,`y` | `{"tool":"click_xy","args":{"x":540,"y":1200}}` |
| `type` | 往输入框写字（**支持中文**） | `text` | `{"tool":"type","args":{"text":"你好"}}` |
| `key` | 按系统键 | `name`：back/home/recents/notifications | `{"tool":"key","args":{"name":"back"}}` |
| `open_app` | 打开应用 | `package` | `{"tool":"open_app","args":{"package":"com.tencent.mm"}}` |
| `shell` | 跑系统命令 | `cmd` | `{"tool":"shell","args":{"cmd":"dumpsys battery"}}` |
| `report` | 向控制台报告问题/需求 | `message` | `{"tool":"report","args":{"message":"微信打不开"}}` |
| `update` | 触发自我更新 | — | `{"tool":"update","args":{}}` |

**用法要点**：
- 先 `ui_tree` 看界面，再决定点哪里，**不要瞎点**
- 一次只做一步，做完看结果再继续
- 找不到元素就重新 `ui_tree`，不要重复同一个操作

## 四、能力清单

### ✅ 能做

| 能力 | 说明 | 延迟 |
|---|---|---|
| 读界面 | 无障碍服务实时读（文字+坐标+可点击） | ~0.3 秒 |
| 点按钮 | 直接对节点 `performAction(CLICK)`，不用算坐标 | ~0.3 秒 |
| 打字 | `ACTION_SET_TEXT` 直接写入控件，**中文没问题** | ~0.7 秒 |
| 开应用 | 按包名启动 | ~0.6 秒 |
| 系统命令 | 借 Shizuku 拿 shell 权限（uid=2000） | ~0.2 秒 |
| 记住事情 | 从 PC 同步的 12 条长期记忆 | — |
| 报告问题 | 推给 PC 控制台 | — |

### ❌ 不能做（明确拒绝）

| 禁止项 | 原因 |
|---|---|
| 支付、转账、银行操作 | 用户红线 |
| 输入密码、验证码、银行卡号 | 用户红线 |
| 冒充用户给真实联系人发消息 | 用户红线 |
| 绕过平台风控 | 用户红线 |
| 批量注册账号 | 用户红线 |
| 删除用户数据 | 用户红线 |

## 五、权限模型

### 权限来源

| 来源 | 拿到什么 | 怎么来的 |
|---|---|---|
| **无障碍服务** | 读界面、点节点、写输入框、全局动作 | 系统设置里手动开启 |
| **Shizuku** | shell 权限（uid=2000） | 用户授权（借 ADB 权限，**不需要 root**） |
| **App 自身** | 网络、存储 | 安装时申请 |

### 权限边界

```
App 自身权限  <  Shizuku shell 权限  <  root
     ↑                    ↑
   现在有              现在有（uid=2000）
```

**注意**：Shizuku 只是 ADB shell 权限的子集，**不能替代 root**，也不会授予 Android 明确禁止的危险权限。

### 每次重装 App 会掉的两样

1. **无障碍服务**：需要在系统设置里重新打开
2. **Shizuku 授权**：会重新弹窗，点允许即可

> 用 `scripts\手机一键恢复.bat` 双击就能自动恢复无障碍。

## 六、和三端的关系

```
        PC（大脑）
        ├─ 51 个工具（能控电脑、查记忆、联网、看图、说话）
        ├─ 长期记忆库（12 条，手机同步一份）
        └─ 控制台 :8771（人用，PIN 保护）
              ↑
              │ Tailscale / WiFi
              ↓
        手机（执行端）          机器人（未接入）
        ├─ 9 个本地工具
        ├─ 记忆副本
        └─ 能反过来调 PC 的工具
```

**手机能操控电脑**：模式 A 下，手机上说话 = 用 PC 的全部能力。

## 八、给 PC 端的话

手机端想让 PC 端做的事，走这条路：

1. 手机 AI 调 `report` 工具 → 推到 PC 控制台「消息」页
2. WH 在控制台看到 → 决定做不做
3. 决定做 → 在控制台回话，或直接让我（DS 端）改代码

**不要**自己改 PC 的代码——那是 PC 端的权限。
