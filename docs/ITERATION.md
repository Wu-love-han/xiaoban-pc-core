# 小伴迭代授权协议（AI 自迭代指南）

> 用户授权 AI 在小伴代码库上做功能迭代。本文件是**边界**，AI 每次改代码前必读。

## 一、能做的（经用户口头授权即算）

- 新增工具（tools/t_*.py）
- 新增 API 路由（server/routes/*.py）
- 新增插件、改前端（web/*）
- 改记忆/情绪/主动行为/直播模块
- 提交并推送到 GitHub（本仓库）
- 打 tag、写 Release

## 二、必须问用户才能做的（不可越权）

1. **花钱**：注册付费服务、买 API、开按量计费的云资源
2. **对外发布**：把 AI 生成内容发到公开平台（直播、发视频、发帖、公开评论）——大肥鱼式运营账号必须用户点头
3. **动别人的设备**：操作手机/其它电脑上不属于测试范围的东西
4. **动凭据**：改 token、账号、密码、密钥
5. **动系统**：卸载软件、改注册表、防火墙、系统服务
6. **删除数据**：删数据库、删日志、删用户文件（除非用户明确说删）
7. **发消息冒充用户**：以用户身份给真实联系人发消息

## 三、红线（永远不做，即使被要求）

- 支付/转账/银行卡操作
- 登录账号代替用户操作
- 获取、传播验证码/密码
- 绕过平台风控、批量注册账号
- 任何违法内容

## 四、GitHub 工作流（自迭代）

1. 每次功能迭代开新分支：`git switch -c feat/<功能名>`
2. 写完 commit：`git add -A && git commit -m "feat: <说明>"`
3. 推送：`git push origin <分支>`
4. 自己测试通过后合并到 `main`
5. 大版本打 tag：`git tag -a vX.Y.Z -m "..." && git push --tags`

## 六、分支约定

- `main`：稳定可跑
- `feat/*`：功能迭代
- 永远不要在 `main` 上直接改崩后端再跑路——改完必须语法检查 + 重启验证
