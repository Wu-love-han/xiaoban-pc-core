# 三个 AI 协作架构（2026-11-05）

## 一句话

**三个 AI 共同扮演「小伴」这一个陪伴角色，各管一摊，通过 PC 中转互相联系。**

---

## 一、三个 AI 是谁

| 名字 | 位置 | 角色 | 能干什么 |
|---|---|---|---|
| **小伴** | PC | 大脑 | 控电脑、记忆主库、协调、装插件、查网页 |
| **小随** | 手机 | 手 | 控手机、遥控电脑、离线工作、本地插件缓存、主动汇报 |
| **小动** | ESP32 | 身体 | 移动、感知环境、语音（**待做**） |

### 为什么这么分

```
小伴（PC）：算力最强、权限最大、24 小时在线 → 当大脑
小随（手机）：随身、能看能点、跟着 WH 走     → 当手
小动（机器人）：能动能看、在物理世界          → 当身体
```

---

## 二、互相通信

### 架构

```
小随 ──┐
       ├──→ 小伴（PC 中转）──→ 小动
小动 ──┘
```

**手机和机器人不直连**，都经过 PC。原因：PC 24 小时在线，是唯一稳定的中转站。

### 接口

```
POST /api/agents/send     {"from_id":"pc","to_id":"phone","content":"..."}
GET  /api/agents/inbox    ?agent_id=phone&limit=10&unread_only=true
POST /api/agents/read     ?agent_id=phone
GET  /api/agents/state    看三个 AI 的身份 + 未读数
GET  /api/agents/recent   最近的消息流水（给用户看协作记录）
```

### 工具（AI 自己用）

**PC 端**：
```
agent.send    {"to":"phone","content":"...","kind":"ask"}
agent.inbox   {"action":"list"} 或 {"action":"state"}
```

**手机端**：
```
agent_send    {"to":"pc","content":"...","kind":"note"}
agent_inbox   {}
```

### 存储

`D:\xiaoban-data\agents.db`，表 `agent_messages`：
```
id, from_id, to_id, kind, content, meta, status, created_ms, read_ms
```

### 实测

```
小伴 → 小随：{"ok":true,"id":1,"content":"小随，测试一下通讯，收到回我"}
小随的收件箱：[小伴] 小随，测试一下通讯，收到回我
```

## 三、手机端（小随）的新能力

### 3.1 主动性

```
✅ 主动给 WH 发消息（发现值得说的、该提醒的）
✅ 主动找小伴要插件、要工具
✅ 主动查网页找答案
```

### 3.2 限时（用户要求）

```
一个任务最多 3 分钟（TASK_LIMIT_MS = 180000）
超时 → 停下来汇报进度，别死磕

超时的话术：
「（超时了，3 分钟到）我做了 N 步：<过程>  停在这了，你看要不要我接着弄。」
```

### 3.3 观后感（用户要求）

任务做完自动写一段，发给 WH：

```
1. 我做了什么
2. 学到了什么 / 新能力是干嘛用的
3. 我的想法（哪里不顺、下次怎么改进）
4. 效果怎么样
```

推给 PC 后存成 `category=reflection` 的记忆（三端同步）。

### 3.4 本地插件缓存

用户要求：「下载的插件是缓存在手机上，这个是你的独特功能」

```
手机端装过的插件缓存本地 → 断网也能用
（这块还要补，现在只有 PC 端装插件）
```
